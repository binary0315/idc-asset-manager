# IDC 资产管理系统（局域网多人版）

基于 **Python 标准库 + SQLite** 的轻量网页应用，用于管理机房光模块/线缆物料台账、库存变动、坏件 RMA 追溯，以及 GB300 机房机柜 46U 视图与部件更换备件。

**零第三方依赖**：不需要 `pip install`，有 Python 3.10+ 就能跑。后端 `app.py` + `idc/` 业务模块，前端 `index.html` + `static/` 资源，数据存本地 SQLite。

---

## 快速开始

### 从 GitHub 获取（推荐）

```bash
git clone https://github.com/binary0315/idc-asset-manager.git
cd idc-asset-manager
python app.py
```

浏览器打开 <http://127.0.0.1:8002>，**首次访问会引导创建管理员账号**（密码至少 12 位，不预置在源码中）。登录后可在「账号权限」里创建协管员。

也可以直接下载 ZIP：GitHub 仓库页 → 绿色 `Code` 按钮 → `Download ZIP`，解压后同样运行 `python app.py`。

### 本机运行

1. 安装 Python 3.10 或更高版本（<https://www.python.org/downloads/>，安装时勾选 *Add Python to PATH*）。
2. 在项目目录执行 `python app.py`。
3. 打开 <http://127.0.0.1:8002>。

### 多人局域网使用

在承载应用的电脑上打开 PowerShell，在项目目录执行：

```powershell
$env:IDC_HOST = "0.0.0.0"
python app.py
```

或直接运行 `python run_lan.py`（效果相同）。其他人通过 `http://服务器局域网IP:8002` 访问，需由网络管理员放行防火墙端口。

> 本版本面向**内网试用**，不自带 HTTPS、单点登录或云端备份。若要放到公网，请置于启用 HTTPS 的反向代理之后。

## 关于数据文件（重要）

**本仓库不包含 `idc_inventory.sqlite3`。** 数据库里有账号密码哈希、登录会话、真实资产数据，因此已通过 `.gitignore` 排除，不会上传到 GitHub。

- 首次启动时程序会**自动建库建表**，并引导创建管理员账号；克隆下来是空系统，需要重新录入数据。
- 想把自己电脑上的现有数据带到另一台机器：直接拷贝 `idc_inventory.sqlite3` 到目标机器的项目目录即可（**不要用 GitHub 传这个文件**）。
- 生产使用请定期备份该数据库文件。

**用环境变量隔离数据库**：设置 `IDC_DB` 可把数据库指向任意路径（父目录不存在会自动创建），用于测试或同时运行多套实例而互不干扰：

```powershell
$env:IDC_DB = "C:\idc-test\isolated.sqlite3"
python app.py
```

不设置时默认使用项目目录下的 `idc_inventory.sqlite3`。数据库路径统一由环境变量决定，不再支持在代码里改 `app.DB`（该符号已移除，读取会直接报错）。

## 功能与数据口径

- **物料台账**：仅光模块、线缆两类。型号是台账与库存变动的唯一关联键，唯一性**不区分大小写、全角/半角与首尾空格**。汇总计算累计入库、已领用/安装、损坏/报废、可用库存与未到数量。
- **库存变动**：每次入库、领用/安装、报废登记一条明细。数量**只接受正整数**（拒绝小数、布尔值、零和负数），**可用库存不允许为负**，超额领用/报废会在同一事务内整笔回滚；报废时按件生成坏件 SN 追溯记录。
- **备件 / RMA**：坏件逐件补录唯一 SN，状态流转（待 RMA、RMA 处理中、已完成、可用备件、报废等）全部留痕。删除会破坏追溯的明细会被阻止。
- **GB300 机房视图**：房间卡片 → 机柜 46U 布局 → 各 U 位部件（NODE_SN、KP_NAME、BMC_MAC）。「部件更换」自动把旧 NODE_SN 登记为服务器备件（初始状态「待检测」）；「信息修正」只纠错、不生成备件。更换历史与备件按**服务器 id** 关联，不跟随 SN 变更，因此修改服务器 SN 不会丢失 46U 视图里的操作记录。
- **回收站 / 操作日志**（仅管理员）：删除物料会保存删除前完整快照（物料字段 + 明细 + 坏件 SN + 状态历史），可查看详情并原样还原；也支持「彻底删除」永久清除。操作日志记录新增、编辑、导入、登记、删除、还原等关键动作。**目前仅「删除物料」进回收站**；删除服务器不进回收站，但会归档其更换历史与备件，删除单条明细只记日志。
- **删除保护**：有关联明细或坏件的物料，需页面内输入完整型号二次确认。删除有关联部件或历史的服务器，同样需输入完整 SN 二次确认，并明确列出 46U 部件、更换历史、备件与状态历史条数。

数据库升级在服务启动时自动幂等执行（`items.model_key` 唯一索引、`deletion_audit` / `operation_log` 表、`server_id` 关联列），存量数据自动回填，无需手工执行 SQL。

**服务器历史归档**：`server_component_operations` 与 `server_spares` 用 `server_id` 关联，迁移时按 SN 回填到现存服务器；匹配不到（原服务器已删除）的记录统一标为「已归档」，**即使之后用同一个 SN 新建服务器也不会错挂到新机器**。备件页会标注「原服务器已删除」并显示当前 SN，管理员可逐条「彻底删除」这些归档备件及其状态历史（更换操作记录保留）；仍关联现有服务器的备件不能单独删除。备件备注最多 500 字。

## Excel 批量导入

物料台账、入库明细、GB300 服务器清单、GB300 46U 部件这**四类导入**都支持 **`.xlsx` 第一张工作表**，且都遵循「上传 → 预览 → 可改映射/数据 → 重新校验 → 确认」的流程：

1. **表头所在行**：扫描前 30 个非空行自动识别，猜错可在下拉框里改。
2. **字段对应**：每一列一个下拉，可手动指定它对应哪个字段或「忽略」。列名不标准、完全无法自动识别时也能进这个界面，**不用回去改 Excel**。纯空列（Excel 里有样式但没内容）会自动隐藏。
3. **预览数据**：单元格可在线修改，每页 50 行分页；**不需要的行可逐行删除，删错了点「恢复已删除的行」**，确认时只写入当前预览中的行。确认时全量复校，失败保留预览可改后再提交。

| | 物料台账导入 | 入库明细导入 |
|---|---|---|
| 必需字段 | 型号、名称/规格、计划数量 | **型号、入库数量**（仅此两项） |
| 类别 | 可表格提供，或整批指定默认值 | 按型号从台账自动带出；表格提供时只做一致性校验 |
| 导入模式 | 新增物料 / 按型号更新台账字段 | 仅入库 |
| 其它 | 更新模式不改动任何库存数量；系统导出的 Excel 可直接回导批量改字段 | 可选日期、位置、负责人、备注；缺日期取导入当天；日期支持 ISO / 斜杠 / Excel 序列号 |

整批校验：文件内重复、台账重复、数量或日期非法、型号不匹配都会带行号阻断，一条不合格则整批不导入。累计入库/领用/报废数量列不会被导入，以免绕过库存变动明细。

**表格没有数量列也能用**：BOM 单常只列型号与规格、不带数量。此时预览把数量暂填 `0` 并给出提示，**不会整批阻断**；在预览表格里逐行补填（入库数量必须是大于 0 的整数，计划数量可为 0），或把不需要的行删掉，再确认导入即可。也仍可在「字段对应」里把某一列手动指定为数量列。确认时无论是否改过预览，服务端都会对最终行集做一次完整复校，绝不会写入数量为 0 的入库明细。

**GB300 服务器清单导入**必需：机房/房间、机柜位置、SN；文件内或台账中重复 SN 会整批阻断。

**GB300 46U 部件导入**必需：`SN`、`NODE_SN`、`NODE`（U 位）、`KP_NAME` 四项；**`BMC_MAC` 为可选**（列可省略、值可为空）。SN 需能关联服务器清单（位置按 SN 带出，源表的机房/机柜列会忽略），NODE 必须是 1–46 的整数，每个 SN 预期 37 条部件（不足只给警告）；确认后按文件中的 SN 替换这些服务器原有的部件清单。

两类 GB300 导入与物料台账、入库明细共用同一套预览规格：自动识别扫描前 30 个非空行、列名不标准也可逐列手动指定、纯空列自动隐藏、每页 50 行分页且单元格可改；点「应用修改并重新校验」由服务端按原始表格重算，确认导入时还会对编辑后的全部行做一次同口径校验（SN 冲突、U 位越界、必填为空等带行号阻断）。

**表头自动匹配采用「精确优先」**：像 gbgInfo 导出表那样同时含 `NODE_SN_KP`、`BF3_BMC_MAC`、`OOB_OS_MAC`、`CX8_*_MAC` 等衍生列时，只有精确的 `SN` / `NODE_SN` / `NODE` / `KP_NAME` / `BMC_MAC` 会被映射，衍生列一律忽略并在预览里给出警告，不会互相冲突或阻断整批。若仍有列对不上，在「字段对应」里手动指定即可。

**确认导入失败不会弄丢预览**：行级校验或数据库事务失败时预览令牌保持有效，修正数据后用同一令牌直接重试，无需重新上传或重新映射；只有确认成功后令牌才会被消费。

## 配置接口（开放化第一步）

`GET /api/config` 无需登录，返回当前所有业务口径：物料类别、台账字段与长度限制、两类备件状态、机柜 U 位数、数量上限、导入参数（扫描行数 / 行数上限 / 分页大小）。目前这些值仍是后端常量，接口带 `configurable: false`；后续改为可配置字典时返回结构不变，前端与导入逻辑无需修改。新增类别、状态或机柜规格时请以这里为准，不要在前端另抄一份常量。

## 安全提示

- 管理员密码至少 12 位，只存 PBKDF2 哈希，不写进源码。
- 首次创建管理员使用数据库独占事务 + 条件插入，并发初始化只会成功一次。
- 会话、CSRF 令牌均在服务端校验；只读账号无法调用写接口。登录失败按 IP+账号限速（5 次后返回 429），且账号不存在时也执行等价哈希运算以消除用户名枚举的时序差。
- 关键写操作支持幂等：前端**唯一的 `api()`** 为每个写动作生成 `X-Idempotency-Key`，覆盖全部 POST / PATCH / DELETE；服务端按 `用户 + 方法 + 路径 + 键` 持久化首次结果，重试/并发回放同一响应，不会重复生成业务记录或操作日志；不同接口使用同一把键会被拒绝。前端只在**明确成功或业务 4xx** 后释放键；网络异常或 5xx 时结果未确定，键会保留供下一次相同提交复用（5 分钟后过期），因此「服务端已写入、浏览器丢响应」重试不会重复入库。裸请求仅对库存变动有 3 秒并发去重兜底，回放响应带 `X-Idempotency-Replay` 标记；格式非法的键直接 400，不会静默忽略。
- 账号用户名统一 3–40 字符、拒绝控制字符，首次初始化与管理员创建协管员使用同一套校验。
- 退出登录只有服务端确认成功（或返回 401 会话已失效）才清理本地状态；网络异常时保持当前界面并提示重试，不会出现「界面退出了但 Cookie 仍有效」。
- 四类 Excel 导入（物料台账、入库明细、GB300 服务器、46U 部件）成功后都会写入批次操作日志（条数与关键口径），便于追溯。请求期间按钮进入禁用并显示「校验中 / 写入中」，成功后提示行数与耗时。
- 幂等回放响应带 `X-Idempotency-Replay: 1`，客户端可区分「实际执行」与「回放首次结果」；首次响应无此头。口径见 `/api/config` 的 `idempotency`。
- 前端交互集中在 `static/app.js`，函数定义唯一（无同名覆盖）；修改或追加功能时请勿再声明同名函数。样式改动放 `static/app.css`。
- 响应统一带 CSP、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` 与 `nosniff`。页面有少量内联事件属性（`onclick`），CSP 放行 `'unsafe-inline'`；经 HTTPS 反向代理部署时会话 Cookie 自动补充 `Secure`。若需嵌入跨源 iframe，可设环境变量 `IDC_FRAME_OPTIONS=` 放开帧限制。
- 静态资源 `app.css` / `app.js` 返回 `ETag` 与 `max-age=3600`，首页按文件修改时间自动追加 `?v=` 版本号；`HEAD` 请求返回与 `GET` 相同的响应头但不带正文，`304` 不携带 `Content-Length`（避免代理误判资源为空）。
- 数量上限、字段长度等口径统一由 `/api/config` 公布，后端所有写入路径共用同一套严格校验。
- 本应用适用于**可信内网**。对外开放前请自行评估认证、传输加密与访问控制。

## 运行内置测试

仓库自带 41 项回归测试（标准库 `unittest`，无需 pip 安装），覆盖模块导入顺序、旧库升级、静态缓存/HEAD/304/204、从初始化到登录/增删改查/库存约束的 API 冒烟，以及前端结构契约（首屏顺序、导入吸附条/折叠、日期默认今天、删除确认、搜索空状态、列排序、机柜空引导、label 关联、移动端）。其中「日期默认今天」用 Node 在 mock DOM 上**真实执行 `setUser()`**，覆盖创建管理员/登录/会话恢复三条路径，而不只是 grep 源码。测试使用临时数据库和随机端口，**不会碰真实数据**，也无需先启动服务：

```bash
python -m unittest discover -s tests -v
```

改完代码先跑一遍；全绿再发版。这些测试专门拦截过去几轮出现过的回退（拆分漏导入导致导出 500、304/204 错带 Content-Length、app.DB 死导入等）。
